# AIDT 前端导航与 IAM 权限批次目标模式

## 🎯 单一目标

从冻结基线 `req-config-center-frozen-v1` 出发，在独立功能分支完成以下三项需求：

1. `IDEA-NAV-001`：可配置组织栏目与工作区导航。
2. `IDEA-IAM-001`：组织、人员、角色和权限配置中心。
3. `IDEA-WFROLE-001`：流程业务角色与节点级授权。

目标不是继续扩展固定页面，而是让授权人员能够通过页面管理：

```text
组织
 → 人员
 → 角色
 → 权限
 → 菜单/工作区
 → 流程业务角色
 → 流程节点处理人策略
 → 后端动作校验与审计
```

## 🚫 冻结与范围边界

- 冻结标签：`req-config-center-frozen-v1`
- 冻结发布：`req-config-center-final3`
- 不修改、移动或覆盖冻结标签。
- 不直接修改已经执行的数据库迁移 `001–008`。
- 新建功能分支，推荐 `feature/frontend-navigation-iam`。
- 新数据库迁移从 `009` 开始。
- 保持现有项目、流程、任务、文件、配置、Agent 和审计数据兼容。
- 不连接真实钉钉、U9、ERP、DCS。
- 不启用真实外部大模型。
- 不把本地演示身份描述为生产 SSO/OIDC/MFA。

本批次必须处理：

- 冻结清单中的 P0“`project-manager` 缺少流程任务审批权限”。

本批次不擅自处理，除非为了完成本批功能所必需：

- 事件状态持久化
- 项目状态持久化
- 文件自动形成项目关系

- 已完成任务仍显示在“我的待办”

如果上述问题影响本批实现，必须修复并写入变更计划；否则保持原状并记录。

## 🧭 NAV-001 实现要求

### 数据模型

允许采用更合适的命名，但必须满足：

- 导航分组/工作区模板
- 导航项
- 导航项排序、显隐、启停和版本
- 导航项与权限资源/动作关联
- 导航项与部门、业务模块、流程视图或业务视图关联
- 个人排序/收藏/隐藏偏好
- 系统保留项标记
- 创建、更新、发布、停用和恢复审计

不得创建与 `Identity.Department` 重复的“部门主数据”。

### 行为

- 平台管理员可以创建“研发部”栏目。
- 创建栏目时可以套用默认模板：
  - 部门工作区
  - 流程事项
  - 业务视图
  - 部门文件
  - 可选项目、听记、报表
- 授权部门负责人只能维护本部门栏目。
- 系统入口不可删除：
  - 我的工作
  - 待办
  - 事件收件箱
- 普通导航项可以隐藏、停用和恢复。
- 删除操作仅停止展示，不删除业务数据。
- 后端必须按当前用户权限返回导航树。
- 前端隐藏和直接路由访问都必须由后端最终拒绝。

### 验收

- 创建“研发部”栏目并自动生成默认入口。
- 隐藏工作区后入口消失，原部门数据仍存在。
- 恢复入口后重新可见。
- 无权限用户访问对应 API 返回 403。
- 390px 可操作且无横向溢出。

## 🏢 IAM-001 实现要求

### 组织

- 支持公司/中心/部门/班组的树形结构。
- 增加父级、路径、类型、排序、负责人和启停状态。
- 支持主职和兼职部门，不复制人员主数据。
- 停用组织前必须检查用户、项目、流程和文件引用。

### 人员

- 用户查询和详情。
- 邀请、开通、停用和重新启用。
- 批量导入。
- 主职部门、兼职部门、部门负责人。
- 数据范围展示和变更。
- 未实现正式邮件邀请时，可以提供受控的本地开通流程，但必须明确边界。

### 角色与权限

- 角色列表、详情、新增、复制、修改和停用。
- 区分：
  - 系统角色
  - 业务角色
  - Agent 服务角色
- 权限目录只读展示，角色权限可配置。
- 用户角色可以按组织/部门范围分配。
- 保留系统角色不可删除。
- 使用中的角色必须先迁移成员或明确阻断停用。
- 禁止用户给自己提升权限。
- 高风险授权必须审计，必要时增加双人审核接缝。

### 数据范围

至少支持：

- 组织
- 部门
- 本人
- 参与项目

必须能解决不同部门经理只看到本部门、平台管理员跨部门的问题。

### 菜单与动作

- 导航项和前端动作必须分别绑定权限。
- 后端 API 权限校验是最终真源。
- 无权限菜单不返回；无权限 API 返回 403。

### 前端页面

至少提供：

- 组织架构树
- 人员与部门归属
- 角色管理
- 角色权限矩阵
- 用户角色分配
- 数据范围配置
- 导航与工作区配置
- 变更影响预览与审计

### 验收

- 创建角色、授予权限、分配给用户后，菜单和 API 权限一致生效。
- 移除权限后重新登录，菜单消失且 API 返回 403。
- 停用使用中的角色被阻止。
- 用户不能自行提权。

## 🔐 WFROLE-001 实现要求

流程节点处理人策略至少支持：

- `SpecificUser`
- `BusinessRole`
- `DepartmentManager`
- `ProjectOwner`
- `InitiatorManager`
- `Agent`

实现要求：

- 配置中心节点选择不再只支持固定用户名。
- 发布前校验角色、部门和范围能否解析处理人。
- 流程实例启动或任务创建时冻结解析结果。
- 历史任务不受后续角色成员变化影响。
- 审批时校验：
  - 当前任务处理人
  - 业务角色资格
  - 节点动作权限
  - 数据范围
- 支持备份处理人、升级和转交，但保留原责任人。
- 高风险动作永久人工边界不变。

专项必须验证：

```text
研发工程师 → 研发业务角色
项目经理 → 经理审核角色
质量工程师 → 质量复核角色
```

真实项目经理必须能够审批分配给自己的经理节点，不得依赖平台管理员兼岗。

## 🗃️ 数据库要求
