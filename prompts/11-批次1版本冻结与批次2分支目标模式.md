# 目标模式提示词：批次 1 版本冻结与批次 2 分支准备

你现在进入目标模式。本轮只处理 AIDT 需求池批次 1 的版本冻结、干净重建、发布验证和批次 2 分支准备。

本轮不是功能开发任务，不实现批次 2 需求。

## 一、执行目标

完成以下顺序：

1. 审查批次 1 工作区改动。
2. 运行批次 1 回归测试。
3. 将批次 1 源码、迁移、测试和文档提交到 `feature/requirement-pool-batch-1`。
4. 将批次 1 分支合并到 `main`。
5. 从干净 `main` 构建新发布包。
6. 部署到本地测试环境并执行 E2E。
7. 验证发布包 manifest 的源版本不再包含 `-dirty`。
8. 创建批次 1 注释标签。
9. 从干净 `main` 创建并切换到 `feature/requirement-pool-batch-2`。
10. 输出批次 2 起始基线。

目标完成状态：

```text
BATCH1_RELEASE_FROZEN_AND_BATCH2_BRANCH_READY
```

## 六、阶段 1：工作区审查

执行：

```powershell
git status --short --branch
git diff --stat
git diff --cached --stat
git log --oneline --decorate -10
git branch --all
git remote -v
```

检查：

1. 当前分支是否为 `feature/requirement-pool-batch-1`。
2. 是否存在不属于批次 1 的用户改动。
3. 是否存在密钥、数据库文件、上传文件、日志、缓存、`bin`、`obj`、`node_modules` 或测试临时文件。
4. 是否存在 Playwright 临时结果需要加入 `.gitignore`。
5. 是否存在不应进入版本库的本地配置。

如果发现来源不明或可能不属于批次 1 的改动：

- 不要擅自提交。
- 记录文件、差异和原因。
- 停止并请求用户确认。

## 八、阶段 3：提交批次 1

只有在阶段 1 和阶段 2 通过后提交。

建议按逻辑拆分：

1. 后端与数据库：

```text
feat(batch1): add department workspace files and environment isolation
```

2. 前端与 E2E：

```text
feat(batch1): add employee workspace department views and file center
```

3. 文档与测试证据：

```text
docs(batch1): record requirement pool delivery and verification
```

要求：

- 不提交密码、密钥、数据库备份和运行数据。
- 不提交 `bin/`、`obj/`、`node_modules/`、`dist/`、`.tmp/`。
- 测试截图如果属于正式证据可以提交；临时 Playwright 结果按 `.gitignore` 处理。
- 提交后工作区必须干净。

如果项目已有更合理的提交拆分方式，可以按现有约定执行，但必须保证变更可理解、可回滚。

## 九、阶段 4：干净分支验证

提交后再次执行：

```powershell
git status --short
git show --stat --oneline HEAD
```

确认工作区没有未提交文件。

在干净特性分支上运行必要的构建和测试。

如果失败：

- 在当前分支修复。
- 重新提交。
- 再次验证。
- 不得带着失败进入 `main`。

## 十、阶段 5：合并到 main

执行非快进合并：

```powershell
git switch main
git merge --no-ff feature/requirement-pool-batch-1
```

要求：

- 使用描述性 merge commit。
- 如果存在冲突，先判断冲突是否仅来自行尾或文档格式。
- 有业务语义的冲突不得自行猜测解决，应停止并报告具体情况。
- 合并后再次确认 `git status --short` 为空。

## 十一、阶段 6：从干净 main 重建发布

版本号使用新版本，不覆盖 `req-batch1-final5`。

推荐版本：

```text
req-batch1-final6
```

执行项目现有发布构建脚本：

```powershell
.\deploy\build-release.ps1 -Version req-batch1-final6
```

验证：

1. 发布包存在。
2. `.sha256` 存在且哈希匹配。
3. manifest 中：
   - `version = req-batch1-final6`
   - `sourceRevision` 不包含 `-dirty`
   - migrationState 正确
   - 003、004 迁移均登记
   - AiGateway 仍为 RuleSimulator
   - 外部系统仍为 Mock/Disconnected
4. 离线依赖和构建证据仍存在或重新通过。

如果 `sourceRevision` 仍带 `-dirty`，不得打最终标签。

先确认当前数据库备份点存在。

执行：


验证：

- Nginx 根路径 200
- API ready 200
- Worker ready 200
- AiGateway ready 200
- Platform capabilities 返回批次 1 完成状态
- 数据库迁移状态为 applied_verified
- 数据库应用表仍为 38

从部署环境重新执行 Playwright：

```powershell
$env:PLAYWRIGHT_USE_EXISTING_DEPLOY='1'
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:8088'
npm run test:e2e
```

要求：

- 5/5 通过。
- 0 failure、0 skipped、0 flaky。

如果失败：

- 不创建最终标签。
- 保留旧部署回滚点。
- 回到批次 1 特性分支修复和重新合并。
