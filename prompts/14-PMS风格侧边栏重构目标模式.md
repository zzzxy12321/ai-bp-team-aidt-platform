# AIDT PMS 风格侧边栏与工作台正文重构目标模式

## 🎯 单一目标

在 AIDT 正式前端仓库完成 `UX-005`，参考用户 PMS 系统的侧边栏和“会议与行动”页面，
分三个阶段统一 AIDT 的应用外壳、导航、正文信息架构和首批业务页面：

```text
UX-005-A 应用外壳与侧栏
 → UX-005-B 统一工作台正文框架
 → UX-005-C “我的工作”和“AI 听记”样板
```

最终体验必须满足：

```text
固定侧栏
 → 简洁页面头与右上角“介绍”
 → 关键统计
 → 搜索与分类筛选
 → 全宽业务主体
 → 清晰的操作结果
```

这不是一次简单换肤。目标是降低页面认知负担，让用户先定位和处理事项，
需要时再查看功能说明，同时保持现有业务契约、权限、审计和数据权威不变。

## 🚦 执行模式

- 这是单一目标模式任务，按 A/B/C 连续执行，但每阶段独立提交、独立验证。
- 先读取、复现、建立影响分析，再修改代码。
- 默认完成到源码、自动化测试、视觉验收截图、规划文档和交付证据。
- 未获得用户明确授权，不合并、不部署、不创建发布包或冻结标签。
- 不把 A/B/C 混成一次无法回滚的大改。
- 同一错误最多三次不同尝试；第三次仍失败，保存证据并报告阻塞。

## 📌 已确认问题

### 侧栏

- `1920×1080` 展开一个部门后，导航高度约 `1917px`，侧栏高度 `1080px`，
  底部约 `837px` 被裁切。
- 正文滚动约 `1680px` 后，侧栏顶部变为 `-1680px`，没有保持吸附。
- Codex 内置浏览器约 `600×518` 时，侧栏高度约 `2031px`，完整导航成为普通页面内容。
- `.sidebar` 使用 `100vh + overflow:hidden`，`nav` 没有独立滚动。
- `.app-layout` 的 `overflow-x:hidden` 形成错误滚动上下文，破坏桌面 `sticky`。

### 正文

- AIDT `.main-content` 固定最大宽度 `1260px`；在约 `2304px` 总视口中，
  可用正文约 `2033px`，内容只占约 `62%`。
- PMS 会议页正文使用接近全部可用宽度。
- “我的工作”标题下有长段说明；已有 4 个统计和 4 个分类页签，但无搜索和组合筛选。
- “我的工作”右侧说明栏约 `337px`，压缩主事项列表。
- “AI 听记”无统计、无搜索、无状态筛选；左右栏约 `289px / 851px`，
  大量来源记录使整页超过 `13000px`。

### PMS 可借鉴模式

- 页面头：标题、范围、主要操作。
- 4 个关键统计。
- 关键词、部门、状态、来源、日期筛选与重置。
- 全宽表格或业务主体。
- 当前部门范围提示。

只参考布局和信息顺序，不复制 PMS 源码、品牌、图标、蓝色主题或 Ant Design。

## 🧩 UX-005-A：应用外壳与侧栏

### 目标

先彻底解决侧栏裁切、滚动消失和窄屏超长，作为后续正文改造的稳定骨架。

### 必须实现

1. 应用外壳为 `100dvh`，主内容在 `.main-column` 中独立滚动。
2. 侧栏保持约 `248px`，不随正文滚动。
3. 品牌/当前部门固定；中间 `nav` 为 `flex: 1; min-height: 0; overflow-y: auto`；
   底部导航偏好和状态固定。
4. 侧栏使用浅色工作台风格，AIDT 绿色只用于品牌和当前状态。
5. 菜单约 `38px` 高、`13px` 字号、`16px` 图标、`8px` 圆角。
6. 分组标题有浅色背景和 `3px` 左侧色条；二级菜单缩进并带细层级线。
7. 当前部门自动展开，其他部门折叠，同一时间只展开一个。
8. 当前菜单变化后 `scrollIntoView({ block: 'nearest' })`。
9. `820px` 以下改为约 `280px` 左侧抽屉，包含遮罩、菜单按钮、Esc 关闭和焦点返回。
10. 保留 `aria-current`、`aria-expanded`、跳到主内容和现有测试标识。

### 禁止

- 仅添加 `overflow-y:auto` 但仍保留错误滚动上下文。
- 在窄屏继续把完整导航堆到正文上方。
- 修改导航 API、发布版本、权限或用户偏好语义。

## 🧱 UX-005-B：统一工作台正文框架

### 页面顺序

```text
页面头
关键统计
搜索与筛选
分类
业务主体
```

### 页面头

- 标题；
- 当前部门、环境或范围短标签；
- 页面主要操作；
- 右上角“介绍”按钮。

移除标题下长期呈现的大段 `page-lead` 功能说明。

### 介绍抽屉

点击“介绍”后从右侧打开约 `420px` 抽屉，必须包含：

1. 这个页面做什么；
2. 什么时候使用；
3. 1～2 个业务操作例子；
4. 权限、数据和人工边界。

示例必须使用真实业务语言，不写系统架构说明。

### 统计

- 3～5 个真实指标。
- 数字必须来自现有 API 或准确聚合；禁止用当前页条数冒充全量。
- 无统计意义的页面不强行生成统计卡。

### 筛选

- 桌面关键词搜索优先占据较宽空间。
- 常用筛选在第一行，重置固定在行尾。
- 移动端首行保留搜索，其余筛选可进入筛选抽屉。
- 筛选结果数量可见；无结果、加载失败和权限拒绝分开处理。

### 主体

- 运营型表格/列表使用完整可用宽度。
- 可设置合理最大宽度，但不得全局固定为 `1260px`。
- 表格固定表头；大量记录使用分页、独立滚动或虚拟列表。
- 详情、表单、长文阅读允许单独设置较窄阅读宽度。

### 组件化原则

优先抽取能明显减少重复的组件，例如：

- 工作台页面头；
- 介绍抽屉；
- 统计条；
- 筛选栏容器。

不要为每个页面制造新的抽象层，也不要一次重写全部页面。

## 🏠 UX-005-C1：我的工作

### 页面头

- 标题：`我的工作`
- 当前部门/全部授权范围
- 操作：`发起事项`，其他动作可收纳
- 右上角：`介绍`

### 统计

- 待我处理
- 今天到期
- 待我确认
- 人工边界

### 筛选

- 搜索标题、项目、业务对象和来源编号；
- 部门；
- 来源类型；
- 状态；
- 优先级；
- 截止时间；
- 重置。

### 分类

- 全部
- 待我处理
- 我发起
- 我参与
- 需要关注

### 主体

- 桌面使用全宽紧凑事项列表或表格：
  `事项 / 来源 / 当前节点 / 负责人 / 截止时间 / 状态 / 操作`。
- 手机使用卡片。
- “今日焦点”保留为一条高优先级横条。
- “快速开始”移入“发起事项”下拉。
- “最近来源证据”改为筛选入口或详情区域。
- 删除长期占用宽度的右侧说明栏；人工边界说明进入介绍抽屉。
- 实际付款、质量放行、配方、设备控制等风险提示仍保留在确认和提交动作附近。

### 必须保持

- 事项打开和深链正确；
- 原有权限、排序、去重和业务详情不变；
- 发起事项、统一确认、证据和听记入口不丢失；
- 现有 E2E 不被删除来规避失败。

## 🎙️ UX-005-C2：AI 听记

### 页面头

- 标题：`AI 听记`
- 当前部门/环境
- 操作：`导入听记`
- 右上角：`介绍`

### 统计

- 听记总数
- 已分析
- 待确认行动项
- 本周新增

### 筛选

- 搜索标题、参会人、文字稿内容；
- 部门；
- 分析状态；
- 行动项状态；
- 来源类型；
- 会议时间范围；
- 重置。

### 主体

```text
┌──────────────────┬─────────────────────────────────────┐
│ 听记来源          │ 当前听记详情                        │
│ 筛选后的列表      │ 状态、文字稿、行动项表              │
│ 固定高度独立滚动  │ 固定高度独立滚动                    │
└──────────────────┴─────────────────────────────────────┘
```

- 左侧约 `300～340px`，右侧占满剩余宽度。
- 来源列表分页、独立滚动或虚拟化，禁止一次渲染全部记录拉长整页。
- 选中记录与右侧详情必须保持对应。
- 分析、行动项编辑、保存、统一确认和真人确认行为不变。
- 钉钉断连和真实模型未启用等背景说明移至介绍抽屉或必要状态标签。

## 🌐 API、数据和权限

默认只消费现有 API：

- `/api/v1/navigation/current`
- `/api/v1/navigation/preferences`
- `/api/v1/my-work`
- `/api/v1/minutes*`
- `/api/v1/departments`

若真实统计无法从现有响应准确取得：

1. 先记录现有契约缺口；
2. 更新影响分析；
3. 允许增加最小只读汇总字段或接口；
4. 同步 DTO、OpenAPI、权限和测试；
5. 不得用前端估算或当前页数据代替全量统计；
6. 不修改写接口、事务和审计。

本需求默认无数据库迁移、无权限语义变化、无新增审计动作。
