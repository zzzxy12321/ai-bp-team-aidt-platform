## 五、本批次锁定范围

### A. AI 听记来源接入

完成手动上传和文字粘贴两条入口：

- 文件中心保留原始听记文件和版本。
- 支持纯文本、Markdown、JSON 文字稿。
- DOCX/PDF 等文件仍可上传保存；如果本批次没有获批的文档解析器，必须明确提示用户粘贴或上传受支持的文字稿，不得伪装解析成功。
- 不实现音频转写。
- 不连接真实钉钉接口。
- 钉钉连接器保持 `Disconnected`，界面必须明确显示“手动导入”或“规则模拟”。

### B. 行动项提取与人工确认

从听记中提取：

- 会议标题、会议时间和来源。
- 发言人及其对应的原文片段。
- 行动项内容。
- 建议执行人。
- 建议截止时间。
- 优先级。
- 建议业务对象类型。
- 建议流程。
- 缺失信息和识别置信度。

每条行动项必须保留：

- 原始听记文件 ID。
- 原文片段。
- 发言人和时间戳。
- AI/规则提取版本。
- 人工修改值。
- 确认人和确认时间。

正确流程：

```text
上传/粘贴听记
  → 建立 MinutesSource
  → AgentRun 生成行动项草稿
  → 人工校对
  → 确认任务草稿
  → 创建业务对象/流程实例或加入已有事项
```

不得由 AI 直接派发任务或直接发起流程。

### C. 行动项转为业务任务

确认后至少支持：

- 将行动项加入现有业务对象和流程实例。
- 在没有现成流程时创建一条明确标记来源的待办或事项。
- 将听记文件和证据关联到新任务/流程。
- 从任务追溯回原始听记、发言人和时间戳。
- 保存幂等键，重复确认不产生重复任务。

不要把“会议记录”复制成新的业务主对象账本。会议是来源，任务是协同记录，业务对象仍是业务主数据。

### D. 流程节点能力包

为流程节点增加可版本化配置：

- 审批人。
- 备份审批人。
- SLA 分钟数。
- 提醒时间和升级时间。
- 超时策略。
- 是否允许数字员工辅助。
- 数字员工可执行的动作范围。
- 金额、风险和执行等级上限。
- 必填附件或前置检查项。

建议至少支持：

- 30 分钟提醒本人。
- 60 分钟升级备份审批人或部门经理。
- 低风险节点可由数字员工生成处理建议。
- 只有显式授权、风险低、可逆的节点，才允许数字员工代理完成。
- 高风险节点只能升级或退回，不能自动通过。

节点策略必须随流程版本冻结到流程实例，不得在流程运行中静默改变历史实例的语义。

### E. 超时 Worker 与幂等

使用 Hangfire/Worker 实现：

- 定时扫描已到期任务。
- 发送站内通知或写入通知记录。
- 触发提醒、升级或 Agent 辅助。
- 相同策略在同一时刻只执行一次。
- 重复扫描、Worker 重启和并发执行不得重复升级或重复执行动作。
- 所有超时、升级、代理和失败动作写审计。

不得等待真实一小时完成测试；使用可注入 Clock、回拨截止时间或测试触发接口验证。

### F. 数字员工受限代理

数字员工必须使用独立服务身份。

代理动作必须满足全部条件：

- 流程节点显式启用代理。
- AgentProfile 处于启用状态。
- 执行等级、风险上限和金额上限满足要求。
- 动作属于低风险、可逆或仅生成处理和证据的范围。
- 使用独立幂等键。
- 审计明确标识 `AgentProxy` 或 `AgentAssist`，不得显示为真人审批。
- 原责任人收到代理结果通知。
- 可撤销或有补偿路径。

永久人工边界：

- 财务付款。
- 质量放行。
- 配方变更。
- DCS/PLC 设备控制。
- 安全联锁。
- 高风险 EHS。
- 外部合同承诺。
- 客户重大赔付。

上述节点即使超时，也只能提醒、升级、退回或保持待处理，禁止数字员工自动批准。

### G. AgentRun 与 AiGateway 串联

至少完成：

- AgentRun 创建后由真人确认进入可运行状态。
- 运行绑定业务对象、流程节点或 MinutesSource。
- AgentRun 调用 AiGateway 时带调用方身份、run ID、模型和超时。
- AiGateway 返回调用 ID、模式、输入/输出摘要和 `ExternalModelCalled`。
- AgentRun 保存调用记录，支持从 Agent 运行反查业务对象、流程任务和听记来源。
- 失败、超时、模型未授权可重试但不得重复产生任务。

真实外部模型默认不启用。如果环境未提供获批的真实模型端点、凭据和数据分级许可：

- 使用 `RuleSimulator` 或确定性结构化解析器完成演示。
- 界面明确显示“模拟结果”。
- `ExternalModelCalled=false`。
- 不得声称已完成真实 AI 接入。

只有同时满足以下条件才能输出
`REQUIREMENT_POOL_BATCH_2_DEMO_COMPLETE`：

1. 一份听记可生成多条行动项草稿。
2. 行动项在人工确认前不会创建任务或发起流程。
3. 确认后可创建任务并追溯到听记文件、原文、发言人和时间戳。
4. 重复确认不会产生重复任务。
5. 流程节点可配置 SLA、提醒和升级策略。
6. Worker 可幂等执行超时提醒与升级。
7. 低风险节点可按显式授权由数字员工代理。
8. 高风险节点无法由数字员工自动通过。
9. 代理动作使用独立 Agent 身份并写完整审计。
10. AgentRun 与 AiGateway 调用可相互追溯。
11. Mock/规则模拟与真实模型状态清晰区分。
12. 普通员工不能跨部门、跨环境或越权读取听记和文件。
13. Domain、Application、SQL、API、前端和 E2E 测试通过。
14. 迁移、备份恢复、部署和回滚验证通过。
15. 需求池、功能地图、权限矩阵、OpenAPI、测试证据和交接文档同步更新。

如果真实模型或钉钉接口未授权，只要 Mock/Adapter、人工确认和边界验证完整，仍可在 Demo 范围内完成；但最终输出必须明确：

```text
真实钉钉接入未完成
真实外部模型调用未启用
本结果只表示批次 2 Demo 完成
```

## 十五、版本与发布

完成后：

1. 按逻辑拆分提交。
2. 确认工作区干净。
3. 从干净批次 2 分支合并到 `main`，使用 `--no-ff`。
4. 从干净 `main` 构建 `req-batch2-final1` 或顺延版本。
5. 发布包 manifest 的 `sourceRevision` 不得包含 `-dirty`。
6. 部署到测试环境并执行健康检查和 E2E。
7. 验证应用回滚与数据库恢复。
8. 创建注释标签 `req-batch2-final1`。
9. 不推送远程，除非用户明确授权。

任何测试失败时不得打最终标签。
