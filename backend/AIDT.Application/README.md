# AIDT.Application

## 📌 职责

用例编排和稳定端口。当前包括：

- `CreateBusinessObjectHandler`
- `ProcessWorkflowTaskHandler`
- `ConfirmAgentRunHandler`
- DTO、分页、错误码映射
- 部门工作区、我的工作与文件中心端口
- 文件扩展名、MIME、签名、大小和 SHA256 校验
- 仓储、工作流引擎、事务、当前用户和时钟接口
- IAM、导航、流程业务角色和任务转交端口
- `UX-003` 统一工作事项纯展示规则：中文状态、风险、优先级分组和去重
- `UX-004-A` 事件人工确认编排：编辑项目/责任人/期限/优先级/内容，按需启动流程，
  与事件确认和项目任务共用单事务
- `UX-004-B` 统一确认：听记业务上下文、MCP 业务视图和四类人工确认来源聚合
- `AGT-003-A` 数字员工治理端口：版本、权限、组织、复核、停用和回滚契约
- `SCN-001-A` 岗位场景端口：目录、不可变版本、生命周期、前置检查、受控启动和高风险审核
- `DEPT-WF-001` 部门流程模板、节点动态字段、任务冻结表单编辑和受控 AI 审查端口

## 🧭 统一工作事项

- `WorkItemViewDto` 是只读展示模型，不是新的业务实体或状态表。
- `WorkItemPresentation` 统一状态中文、风险标签和六级排序。
- 聚合来自 Workflow、PMO、Minutes、Agent 和 MCP；具体权限仍在 Infrastructure 查询和原详情 API 中执行。

## 🧪 事务约束

- 一个用例对应一个明确事务。
- 外部系统调用不进入事务，通过 Outbox 交给 Worker。
- 任务动作要求幂等键和版本校验。
- 审计、业务写入和 Outbox 必须同一事务提交。
- 数字员工发布和停用使用显式 Revision/Version，并复用现有幂等与双人审核。
- 场景启动在一个事务内复用对象、流程、事件收件箱、项目任务、文件和 Agent 服务，
  只保存场景版本到真实业务链 ID 的映射。
- 任务通过、退回、终止时，表单值、冻结定义哈希校验、任务动作、审计和 Outbox
  在同一事务提交；前端 required 不作为安全边界。

## 🚧 边界

组织、导航和流程角色均通过 Application 端口调用，不把 EF 实体暴露给 API。
当前身份仍为本机演示接入；正式 SSO/OIDC 后续接入。
