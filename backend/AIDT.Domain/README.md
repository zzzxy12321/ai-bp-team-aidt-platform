# AIDT.Domain

## 📌 职责

纯领域规则，不依赖 EF Core、ASP.NET Core、HTTP 或外部系统。

核心模型：

- 业务对象与对象类型
- 流程实例、任务和通过/退回/终止状态
- 用户、权限与数据范围
- 部门、成员关系、主部门和部门负责人
- 组织树、角色分类、范围化角色分配和高风险授权规则
- 导航工作区、版本、入口、系统保留项和个人偏好规则
- 流程处理人策略、任务候选人快照、原责任人和转交
- 文件记录、版本、扫描状态、保密等级和删除申请
- `demo/test/prod` 数据环境代码
- 不可变审计事件
- Agent 等级、限额、风险和人工确认
- 数字员工编码、独立服务身份、生命周期、不可变版本和发布快照规则
- 数据/模型/工具白名单、永久人工边界、确认规则与熔断条件
- Outbox 幂等消息
- 岗位业务场景生命周期、版本状态、启动方式和永久人工边界规则
- 节点动态字段来源、任务冻结表单、字段/角色/范围校验和受控 AI 审查边界

## 🧠 已验证规则

- 业务对象使用显式版本做乐观并发。
- 已归档对象不能修改。
- 流程实例固定定义版本和业务对象标识。
- 已处理任务不能重复处理。
- 退回必须填写原因。
- 付款、质量放行、设备控制和高风险 Agent 动作必须有人工确认。
- 数字员工不能确认自己的运行。
- 未发布、已停用或校验失败的数字员工不能发起新运行或签发新授权。
- 已发布数字员工版本不可原址修改；回滚必须创建新版本。
- 文件物理路径不进入前端；敏感或核心文件带人工扫描状态。
- 新业务对象、流程实例和任务必须带部门和环境代码。
- 场景发布版本不可原地覆盖；回滚必须复制为下一新版本。
- 场景必须保留七类永久人工边界，不得让数字员工自动签认或替代高风险动作。
- 任务表单来源只能是业务对象引用、任务输入或证据引用；发布模板不改写历史任务。
- 付款、质量放行、配方变更、设备控制、安全联锁、外部合同承诺和客户重大赔付
  永久保留真人处理。
