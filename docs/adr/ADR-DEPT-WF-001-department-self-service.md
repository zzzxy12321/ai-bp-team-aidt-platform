# ADR-DEPT-WF-001：部门流程负责人自助维护普通流程

- 状态：`Accepted`
- 日期：2026-11-03
- 关联需求：`DEPT-WF-001`

## 🎯 背景

现有冻结需求将 L2 部门配置定义为“部门负责人维护、平台审核”。为了让部门流程负责人
能及时维护普通流程，需要在同一权限、审计、版本和 Elsa 流程真源内开放受限自助能力。

## ✅ 决策

1. 新增范围化角色 `department-flow-owner`，只通过 `UserRoleAssignment` 的
   `department` scope 生效；不得仅按角色名称判断权限。
2. 部门流程负责人可创建、编辑、校验和试运行本部门普通模板。
3. 低风险、单部门、无永久人工高风险动作和被禁止对象类型的模板，可由部门流程负责人发布。
4. 以下情形继续由平台管理员审核发布：
   - 跨部门处理人或跨部门业务对象；
   - 财务付款、质量放行、配方变更、设备控制、安全联锁、外部合同承诺、
     客户重大赔付；
   - 对象类型或流程能力被平台标记为高风险；
   - 引用未注册动作、任意脚本、SQL、HTTP、HTML、JavaScript 或外部写入。
5. 普通员工只能使用当前部门、已发布、非测试模板，不能管理配置。
6. 服务身份不能创建、发布、审核或启动流程。
7. 平台管理员可管理全组织模板；高风险变更仍保留人工审核和永久人工边界。
8. 部门负责人不能通过直接 ID、伪造部门参数、跨部门人员候选或跨部门 Agent
   绕过部门范围。

## 🧱 权限与审计

- 复用 `configuration:read/create/update/approve`，不创建第二套配置权限体系。
- `department-flow-owner` 仅获得上述已有动作及其它只读依赖，不获得流程引擎内部管理权限。
- 发布、停用、恢复、回滚、表单提交、数字员工建议和人工边界拒绝均写追加式审计。
- 任务动作继续校验当前处理人、冻结业务角色候选、部门范围、ExpectedVersion 和幂等键。

## ⚠️ 后果

- 平台团队保留高风险和跨部门审核职责。
- 部门自行发布的普通模板必须通过自动风险分类；分类不确定时升级平台审核。
- 历史模板版本和任务表单不因后续发布或停用而改变解释。
- 生产上线前仍需甲方确认部门负责人名单和审批制度；Demo 角色分配不冒充正式组织制度。
