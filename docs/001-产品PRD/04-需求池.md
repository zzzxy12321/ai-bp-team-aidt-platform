# AIDT 下一阶段需求池

> 版本：V0.1  
> 建立日期：2026-10-31  
> 状态：持续收集与评审中  
> 定位：保存尚未正式进入冻结需求、实施计划或开发范围的产品想法  
> 重要说明：本文件中的条目是“候选需求”，不是已经承诺的功能

## 📖 使用规则

1. 新想法先进入本文件，不直接修改冻结的 `01-需求基线.md`。
2. 每条需求使用稳定编号，编号一旦发布不随意改名。
3. 需求通过评审后，再升级到正式需求、实施计划和功能地图。
4. 涉及身份、权限、审计、外部系统或数字员工高风险动作的需求，必须同时记录安全边界。
5. 需求完成时，保留其来源、决策、验收和最终去向。

## 🏷️ 状态定义

| 状态 | 含义 |
|---|---|
| `inbox` | 已收集，尚未分析 |
| `evaluating` | 正在澄清场景、边界、价值和成本 |
| `approved` | 已批准进入正式需求或实施计划 |
| `deferred` | 暂缓，保留为后续候选 |
| `rejected` | 评估后不采用，记录原因 |
| `implemented` | 已完成并形成交付证据 |

## 🚦 优先级定义

| 优先级 | 含义 |
|---|---|
| `P0` | 没有它，下一阶段核心闭环无法成立 |
| `P1` | 明显提升全员可用性、效率或治理能力 |
| `P2` | 规模化、增强或特定场景优化 |

## 🧭 当前背景

当前 AIDT 全阶段 Demo 已具备：

- 本地演示身份、角色权限和数据范围。
- 业务对象、流程实例、任务、审批和审计。
- 文档、附件、版本和签名的数据表基础。

- AgentRun 与 AiGateway、业务对象和流程实例的完整关联。
- 真实大模型和企业外部系统接入。

## 🏢 IDEA-DEPT-WF-001：部门优先工作空间与可视化流程设计器

- 状态：`implemented`
- 正式 Feature ID：`DEPT-WF-001`
- 优先级：`P0`
- 来源：现有平台已具备导航、配置、Elsa 流程、任务、对象、文件、听记、
  数字员工和审计能力，但后台仍以模块集合组织，普通业务人员需要理解技术对象；
  部门流程负责人也无法在可视化工作台内安全维护本部门普通流程。
- 业务目标：
  - 左侧按公司公共入口、部门、平台治理三层组织；
  - 每个部门提供概览、流程事项、流程配置、部门文件、AI 听记、业务视图、
    岗位业务场景和数字员工身份；
  - 部门可维护同业务对象类型下的多个流程模板和部门默认模板；
  - 节点支持处理人、SLA、动态字段、附件、数字员工、受控 AI 评论、
    通知升级、完成条件和永久人工边界；
  - 运行时按冻结版本展示和保存动态表单，历史任务不受新模板影响。
- 权限边界：
  - 普通员工只使用本部门已发布模板；
  - 部门流程负责人只能管理本部门普通、低风险、单部门模板；
  - 跨部门、付款、质量放行、配方变更、设备控制、安全联锁、
    外部合同承诺和客户重大赔付继续平台审核或永久人工；
  - 服务身份不能创建、发布、审批或启动流程。
- 验收目标：
  - 导航无测试残留、公共入口只出现一次、部门隔离和重新登录状态正确；
  - 模板生命周期、节点字段、版本冻结、任务表单、权限、幂等、并发和审计完整；
  - 交付中心、研发、供应链、财务四部门试点闭环；
  - 迁移 018、全量回归、正式部署、应用回滚、数据库恢复和冻结全部有证据。
- 正式去向：
  - 变更计划：`docs/project/CHANGE_PLAN_DEPT_WF_001.md`
  - 影响分析：`docs/project/IMPACT_ANALYSIS_DEPT_WF_001.md`
  - 上下文包：`docs/project/CONTEXT_PACK_DEPT_WF_001.md`
  - ADR：`docs/adr/ADR-DEPT-WF-001-department-self-service.md`
  - 交付报告：`docs/project/DEPT_WF_001_DELIVERY.md`

## 🧭 IDEA-SCN-001：岗位业务场景目录与场景启动

- 状态：`implemented`
- 正式 Feature ID：`SCN-001`
- 优先级：`P0`
- 来源：平台已有对象、流程、文件、听记、项目、唯一数字员工和权限能力，
  但普通用户缺少按岗位和业务目标组织的入口、准备清单、执行路径与结果证据。
- 业务目标：把现有业务能力组合成可理解、可校验、可追溯的岗位场景，
  让员工先选择“我要完成什么业务结果”，再进入受控对象、流程、任务和证据链。
- 当前缺口：
  - 业务能力分散在建模、流程、项目、文件、听记和数字员工页面；
  - 普通员工需要自行判断对象类型、流程版本、准备材料和人工边界；
  - 缺少场景版本、发布冻结、停用/恢复/回滚及启动记录；
  - 场景引用失效或无权限时缺少统一业务语言拦截。
- 核心模型：
  - 场景是现有能力的受控组合，不是第二套业务系统；
  - 场景版本冻结对象类型、流程版本和数字员工稳定编码；
  - 启动只生成真实业务链映射，不复制对象字段、流程状态、任务状态或审计账本。
- 首批基础场景：
  - 研发样品到转产；
  - 采购请购到到货验收；
  - 财务付款人工复核；
  - 部门经理事项分派与审批；
  - 项目经理里程碑与风险；
  - 质量异常到 CAPA。
- 权限与审计：
  - 平台管理员管理全平台场景；
  - 部门负责人维护本部门场景，不得超过部门、对象、流程和 Agent 权限上限；
  - 普通业务人员只能查看并启动当前有效、已发布且部门可用的版本；
  - 服务身份不能创建、发布、审核或启动场景；
  - 场景发布、停用、恢复、回滚和启动均写追加式审计与 Outbox。
- 永久人工边界：
  - 财务付款、质量放行、配方变更、设备控制、安全联锁、外部合同承诺和客户重大赔付；
  - 场景和数字员工只能提供材料、建议、校验或草稿，不能替代真人签认。
- 验收目标：
  - 六类基础场景有真实后端定义并可启动；
  - 生命周期、权限、幂等、失败回滚、历史版本和引用失效均有自动化测试；
  - 启动结果可从真实对象反查流程、任务、项目、文件、审计和 AgentRun；
  - 现有四类流程和 AGT-003 无回归。
- 当前分段：
  - `SCN-001-A`：岗位业务场景目录与场景启动后端；
  - `SCN-001-B`：岗位业务场景中心、七步启动向导、我的场景、配置治理和试用闭环。
- 正式去向：
  - 7A 变更计划：`docs/project/CHANGE_PLAN_SCN_001_A.md`
  - 7A 影响分析：`docs/project/IMPACT_ANALYSIS_SCN_001_A.md`
  - 7A 上下文包：`docs/project/CONTEXT_PACK_SCN_001_A.md`
  - 7A 交付报告：`docs/project/SCN_001_A_DELIVERY.md`
  - 7B 变更计划：`docs/project/CHANGE_PLAN_SCN_001_B.md`
  - 7B 影响分析：`docs/project/IMPACT_ANALYSIS_SCN_001_B.md`
  - 7B 上下文包：`docs/project/CONTEXT_PACK_SCN_001_B.md`
  - 7B 交付报告：`docs/project/SCN_001_B_DELIVERY.md`
- 7B 已完成：
  - `/scenarios` 以业务语言回答“办什么、准备什么、下一步谁处理、结果和证据在哪里”；
  - 六类场景从网页真实发起，使用现有对象、流程、任务、文件、听记、项目和 Agent；
  - “我的场景”由服务端读取真实启动、流程、任务、项目和事件状态，不在前端保存第二套进度；
  - 配置中心入口支持草稿、校验、发布、停用、恢复、版本和回滚；
  - 数字员工和永久人工边界在发起前明确展示，AI 听记仍须真人确认。

## 💡 IDEA-UX-001：员工优先的业务入口

- 状态：`implemented`
- 正式 Feature ID：`UX-001`
- 优先级：`P0`
- 来源：用户反馈当前系统更像后台软件
- 业务目标：让普通员工进入系统后先看到“我今天要办什么”，而不是业务对象、流程节点和 TraceId
- 目标用户：研发、采购、财务、质量、生产、项目经理、部门经理
- 期望体验：
  - 我的待办、我发起的、我参与的、我负责的项目
  - 异常、逾期和需要补充材料的事项
  - 一个可直接对数字员工说明需求的统一入口
  - 用业务卡片展示事项，不默认暴露 UUID、版本号和节点代码
- 管理员入口：
  - 对象建模、流程配置、权限、连接器、Agent 和审计仍保留
  - 仅平台管理员或配置人员可见
- 验收标准：
  - 新员工无需理解“业务对象”和“流程实例”也能发起一项事项
  - 员工能在一个页面看到当前事项、下一步、负责人和证据
  - 管理员能力与员工能力有明确菜单分层
- 风险与边界：
  - 不允许为了简化界面隐藏审计、风险提示或人工确认
- 正式去向：批次 1 已实现；交付报告 `docs/project/REQUIREMENT_POOL_BATCH_1_DELIVERY.md`

  - 我的工作展示今日焦点、待我处理、我发起、我参与、需要关注和最近来源证据

  - 员工主卡片不显示 UUID、TraceId、节点英文代码、数据库字段或内部 revision
  - Agent 和 MCP 高风险事项继续保留真人确认
- 验收标准：
  - 至少 WorkflowTask、ProjectTask、EventInbox 和 MCP Confirmation 真实聚合
  - 已完成事项不重复显示，无权限事项不可见
  - 点击后进入正确现有详情
  - 刷新和重新登录结果一致
  - 原有 19 项 E2E 不回归
- 正式去向：已实现、部署并冻结；发布 `req-ui-step1-final1`，
  冻结标签 `req-ui-step1-frozen-v1`，交付报告

## 💡 IDEA-UX-004：业务可编辑的人工确认中心

- 状态：`implemented`
- 正式 Feature ID：`UX-004`
- 优先级：`P0`
- 来源：统一工作中心的待确认事件目前只能接受或拒绝建议，业务人员无法在确认时完整修正项目、
  负责人、截止时间、优先级、内容和流程去向
- 业务目标：把“AI 建议 → 真人判断 → 创建任务/关联或发起流程”升级为可编辑、
  可预览、可审计、原子完成的人工确认闭环
- 目标用户：事件提出人、项目经理、部门负责人、被指派的处理人
- 期望行为：
  - 确认前明确选择处理事项、项目/业务对象、负责人、截止时间、优先级和最终内容
  - 明确选择是否创建任务、关联已有流程或发起新流程
  - 使用姓名和业务名称，不要求用户输入 UUID
  - 截止时间按 `Asia/Shanghai` 显示和处理，不得出现次日偏移
  - 最终确认前展示创建对象、通知对象、项目关联、流程启动和不会执行的高风险动作
  - 缺负责人或截止时间时禁止最终确认
  - 任务和流程编排由服务端单事务完成，禁止 Vue 页面串联多个写请求
  - 任一步失败不得留下事件已确认、任务或流程半成品
  - 同一事件不能重复创建任务或重复发起流程
- 分段范围：
  - `UX-004-A`：事件确认与流程发起闭环
  - `UX-004-B`：听记、MCP、Agent 与统一确认中心
- 权限与审计影响：
  - 保持现有事件确认、项目任务和流程启动权限
  - 同时校验组织、部门、项目、处理人和流程可见范围
  - 记录事件来源、项目关系、任务、流程实例和确认影响摘要
- 安全边界：
  - 不改变财务付款、质量放行、配方变更、DCS/PLC 控制、安全联锁、合同承诺和
    客户重大赔付等永久人工边界
  - 不允许通过前端拼接请求绕过事务、幂等或权限校验
- 正式去向：UX-004 已完整实现、正式部署并冻结。
- 2A 发布：`req-ui-step2a-final1`。
- 2B 最终发布：`req-ui-step2-final1`，合并提交 `931f953`，正式 E2E 29/29。
- 冻结标签：`req-ui-step2-frozen-v1`。

## 🧭 IDEA-UX-005：PMS 风格侧边栏与工作台正文重构

- 状态：`implemented`
- 正式 Feature ID：`UX-005`
- 优先级：`P1`
- 来源：当前 AIDT 侧边栏在主页面滚动后随页面离开视口，左侧出现空白；
  打开部门工作空间后菜单高度超过侧栏并被裁切；Codex 内置浏览器窄侧栏会把完整导航
  铺成超长页面。同时，运营页面正文固定在约 `1260px`、只占宽屏可用区域约三分之二，
  标题下长说明挤占首屏，列表缺少搜索和分类，用户难以快速定位信息。
- 参考：用户 PMS 网站的侧边栏和“会议与行动”正文，仅参考
  “页面头、统计、搜索筛选、分类、主体内容、导航抽屉”等信息结构，
  不复制其品牌、源码、图标、蓝色主题或组件库。
- 业务目标：
  - 桌面端保持侧栏固定，主内容和导航分别滚动；
  - 导航中间区域可独立滚动，品牌区与底部操作固定；
  - 只展开当前部门，降低部门入口的纵向占用；
  - 当前入口自动进入可视区域；
  - `820px` 以下改为可关闭的抽屉导航，覆盖 Codex 侧栏与移动端；
  - 运营型页面统一为“页面头 → 关键统计 → 搜索筛选 → 分类 → 业务主体”；
  - 标题下长说明移入右上角“介绍”抽屉，正文优先展示可操作信息；
  - 首批改造“我的工作”和“AI 听记”，验证后再推广到其他模块。
- 视觉目标：
  - 侧栏改为浅色工作台风格，AIDT 绿色用于当前项和品牌强调；
  - 保留当前 `248px` 宽度，菜单约 `38px` 高；
  - 分组标题使用浅色背景和 `3px` 左侧色条；
  - 二级菜单使用缩进和细竖线表达层级；
  - 运营页使用完整可用宽度，表格、筛选和统计保持同一纵向基准；
  - “介绍”从右侧以约 `420px` 抽屉打开，包含用途、场景、1～2 个例子和权限边界。
- 非目标：
  - 不修改导航 API、数据表、路由、权限过滤或发布逻辑；
  - 不新增依赖或数据库迁移；
  - 不在首批中一次性重构所有业务页面；
  - 不把所有详情页和表单强制铺满屏幕；
  - 不用前端当前页条数冒充全量统计。
- 验收目标：
  - 主内容滚动后桌面侧栏保持固定；
  - 展开部门后导航可滚动至底部，底部操作始终可达；
  - `600×518` 和 `390×844` 使用抽屉且无横向溢出；
  - “我的工作”具备真实统计、搜索、组合筛选、分类和全宽事项列表；
  - “AI 听记”具备真实统计、搜索、筛选和左右独立滚动；

  - 避免智能体直接连接数据库、任意调用内部接口或绕过权限

  - Codex 和其他标准 MCP 客户端
  - 受控数字员工服务身份

  - 提供独立 `AIDT.Mcp` 服务，复用现有 Application Service 和领域规则，不复制业务逻辑
  - 同时支持：
    - 本地 `stdio` 模式，供本机 Codex 和桌面智能体启动
    - 远程 Streamable HTTP 模式，供 ECS 部署后的多客户端连接
  - 提供浏览器授权流程；用户选择可用组织、部门和工具范围后签发短期令牌

  - 令牌不得写入源码、普通日志、聊天内容或前端 localStorage

    - 事件收件、Agent 分析、真人确认和来源反查
    - 流程实例与待办查询
    - 流程任务通过、退回和转交
    - 文件元数据、上传和受控下载
    - 导航和当前工作区读取
  - 支持 MCP Resources，用于读取已授权并脱敏的项目、事件、任务、流程和文件资源
  - 所有 MCP 工具调用必须携带或关联：
    - 组织与用户/服务身份
    - 客户端 ID
    - MCP Tool 名称
    - AgentRunId（如由数字员工发起）
    - TraceId、幂等键和最终业务结果
  - 提供 AIDT 内的 MCP 管理页面，用于查看工具目录、已授权客户端、令牌状态和调用审计

  - 无权限工具、跨部门数据、跨项目数据和停用令牌均被拒绝

- 业务目标：建立可治理、版本化、可审计的业务对象元数据，并让授权管理员安全编辑业务对象实例
- 目标用户：平台管理员；部门负责人只按现有授权范围使用业务对象，不获得建模能力
- 当前行为：
  - `GET /api/v1/object-types` 和业务对象查询/创建已存在
  - `POST /api/v1/object-types` 与 `PUT /api/v1/business-objects/{id}` 返回 501
  - 对象类型和字段属性主要由受控种子与历史迁移维护
- 期望行为：
  - 对象类型支持草稿、编辑、校验、发布、停用、恢复、版本历史和乐观并发
  - 字段支持 Text、LongText、Number、Date、DateTime、Boolean、Select、User、Department
  - 字段包含 Key/Code、显示名、必填、最大长度、默认值、敏感等级、选项、列表显示、筛选和排序
  - 已发布版本不可原地修改；变更生成新版本；历史业务对象快照不被改写
  - 业务对象更新校验字段类型、必填、长度、选项、稳定编码和对象类型
  - 更新递增版本、写业务对象版本快照和审计，并以 `expectedVersion` 防止覆盖
- 验收标准：
  - 授权管理员可完成对象模型全生命周期，普通员工直接调用返回 403
  - 现有 CUSTOMER_SAMPLE、QUALITY_DEVIATION、PURCHASE_REQUEST、CUSTOMER_COMPLAINT、PROJECT 无需重建
  - 工作流继续通过 `objectTypeCode` 引用，PROJECT 与 PMO 服务兼容
  - Core 字段对非平台管理员继续脱敏
  - 新增迁移仅 013，001–012 不改动
- 权限与审计影响：
  - 新增 `object-model:read/create/update/manage/approve`
  - 补齐并验证 `business-object:update`
  - 所有创建、草稿保存、校验、发布、停用、恢复和业务对象编辑写追加式审计
- 安全边界：
  - 字段值只作为受限动态数据进行类型和长度验证，不执行脚本、SQL 或任意表达式
  - 已发布模型版本、历史字段和业务对象快照不可被覆盖
  - Core 字段继续按现有平台管理员规则显示，其他身份读取为 `***`
- 依赖事项：
  - Metadata.ObjectType、FieldDefinition、BusinessObject、BusinessObjectVersion
  - Identity 权限与部门范围
  - Workflow `objectTypeCode` 契约和 PMO PROJECT 扩展
- 父需求拆分：
  - `META-001-A`：后端对象建模、字段编辑、版本与权限；已实现并冻结
  - `META-001-B`：业务建模工作室、动态表单、版本/关联证据和跨模块联动；已实现
