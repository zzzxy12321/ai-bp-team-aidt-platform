# AIDT 产品规划总入口

> 版本：V1.0  
> 建立日期：2026-10-31  
> 定位：AIDT 项目目标、需求基线、技术架构、实施计划和下一阶段需求池的统一入口  
> 使用原则：基线文档保持单一真源，新想法先进入需求池，确认后再升级为正式需求或计划

## 📚 阅读顺序

1. [00-项目目标.md](./00-项目目标.md)：为什么做 AIDT，以及最高交付原则。
2. [01-需求基线.md](./01-需求基线.md)：已确认的产品范围、边界、原则和验收口径。
3. [02-技术栈与架构.md](./02-技术栈与架构.md)：冻结技术栈、系统架构和模块边界。
4. [03-计划方案.md](./03-计划方案.md)：已确认的实施阶段、里程碑和验收门槛。
5. [04-需求池.md](./04-需求池.md)：尚未正式纳入基线、等待统一评审的新想法。

## 🗂️ 文档职责

| 文档 | 当前性质 | 允许的更新方式 |
|---|---|---|
| `00-项目目标.md` | 长期目标基线 | 产品方向发生正式调整时更新 |
| `01-需求基线.md` | 冻结需求基线 | 通过变更单或 ADR 后更新 |
| `02-技术栈与架构.md` | 冻结技术基线 | 通过 ADR 和技术评审后更新 |
| `03-计划方案.md` | 冻结实施计划 | 完成范围评审和排期确认后更新 |
| `04-需求池.md` | 持续更新的活文档 | 随时收集，不直接视为已承诺功能 |

## 🔄 需求流转

```text
新想法
  ↓
04-需求池.md
  ↓ 业务价值、范围、风险和优先级评审
正式需求变更
  ↓
01-需求基线.md
  ↓ 排期和阶段确认
03-计划方案.md
  ↓ 开始实施
CHANGE_PLAN + FEATURE_MAP
  ↓ 验收完成
测试证据、交付文档和运行记录
```

## 📌 单一真源规则

- 同一份产品或项目文档只保留一个正式版本，不复制多份到不同目录。
- 需求池中的条目未经批准，不得直接宣称已进入开发计划。
- 已批准需求必须同步更新需求基线、计划方案、功能地图和对应变更计划。
- 历史执行记录保留原文，不通过重写历史掩盖范围变化。
