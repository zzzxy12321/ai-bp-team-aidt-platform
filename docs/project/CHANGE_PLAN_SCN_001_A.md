# SCN-001-A 变更计划

> Feature：`SCN-001 / 7A`
>
> 分支：`feature/ui-step7a-scenario-catalog-backend`
>
> 目标发布：`req-ui-step7a-final1`
>
> 冻结标签：`req-ui-step7a-frozen-v1`

## 🎯 目标

建立岗位业务场景目录与受控启动后端。场景负责组织已有能力、准备材料、
执行步骤和结果证据；真实对象、流程、任务、文件、听记、项目、AgentRun、
审计和 Outbox 继续由原模块负责。

## ✅ 本段范围

- 场景当前态、不可变版本和启动映射。
- 创建草稿、更新草稿、校验、发布、停用、恢复、版本查询和回滚。
- 六类基础场景真实定义。
- 当前用户可见场景列表、场景详情和启动前置检查。
- 受控启动 API，复用现有业务对象、流程、事件收件箱和项目任务服务。
- 权限、部门范围、幂等、引用冻结、失败回滚、审计和 Outbox。
- OpenAPI、后端 DTO、错误码和前端 TypeScript 契约类型。
- 迁移 017、隔离库 up/down/re-up、主库应用、部署和独立恢复。
- 更新需求池、功能地图、权限矩阵、测试证据和交付文档。

## 🚫 非目标

- 不建设 7B 场景中心、启动向导或管理页面。
- 不复制业务对象字段、流程实例状态、任务状态或审计账本。
- 不绕过现有业务服务直接写 WorkflowInstance、WorkflowTask 或 BusinessObject。
- 不连接真实钉钉、U9、ERP、DCS 或外部大模型。
- 不让数字员工自动付款、质量放行、变更配方、控制设备、解除联锁、
  承诺合同或处理重大赔付。

## 🧱 数据设计

| 表 | 责任 |
|---|---|
| `Scenario.ScenarioDefinition` | 稳定编码、名称、所属部门、当前生命周期和当前发布版本指针 |
| `Scenario.ScenarioVersion` | 不可变发布版本、业务配置、引用快照、校验与影响分析 |
| `Scenario.ScenarioLaunch` | 场景版本到真实业务链 ID 的启动映射和幂等结果 |

JSON 字段均增加 `ISJSON` 约束。场景编码在组织内唯一，版本号在场景内唯一。

## 🛡️ 权限与状态

- `scenario:read/create/update/manage/approve`。
- 平台管理员管理全组织；部门负责人只管理授权部门；
  普通人员只查看和启动已发布、有效且部门适用的场景。
- 服务身份拒绝所有场景治理和启动写动作。
- 已发布版本禁止原地修改；修改生成新草稿。
- 停用只阻止新启动，不删除历史版本、启动记录和真实业务链。
- 回滚从历史发布版本复制出新版本，不切换或改写旧版本。

## 🧪 验证计划

- Domain：状态转换、永久人工边界、启动模式、不可覆盖规则。
- EF：模型约束、JSON、唯一键、索引。
- SQL/API：生命周期、可见性、越权、引用失效、必填材料、六场景启动、
  幂等、失败回滚、历史版本、从业务链反查证据。
- 全量后端、MCP、OpenAPI、前端类型、Vitest、构建和 Playwright 回归。
- 迁移 017 up/down/re-up，正式部署、应用回滚和独立数据库恢复。
