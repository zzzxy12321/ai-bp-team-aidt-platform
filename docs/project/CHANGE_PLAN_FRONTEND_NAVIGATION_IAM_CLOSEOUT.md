## 🧩 收尾范围

### 1. 部门级业务角色候选收敛

- `organization` 范围角色成员可作为组织级候选。
- `department` 范围角色成员仅在 `ScopeReference` 等于任务 `workflowDepartmentId` 时成为候选。
- 研发节点不得选入质量、财务、供应链等其他部门成员。
- 研发角色没有研发成员时，发布校验或任务创建必须明确阻断。
- 已创建任务继续使用冻结候选快照，不因角色成员后续变化而回算。

### 2. IAM 操作边界和权限委派上限

- 平台管理员可维护全组织角色、权限、用户角色和导航。
- 项目经理/部门负责人只能管理授权部门内允许的业务角色与导航。
- `organization` 范围角色分配仅平台管理员可执行。
- 成员查询、增加、移除、全量替换都必须校验操作者部门范围。
- 全量替换只允许替换操作者有管理权的部门成员，范围外成员保持不变。
- 修改全局角色权限必须同时具备角色管理、权限委派能力，并满足操作者自身有效权限上限。
- 保留自提权阻断、高风险双人审核和普通只读用户禁止写入。

### 3. 使用中角色统计

- 合并统计兼容的 `Identity.UserRole` 与范围化 `Identity.UserRoleAssignment`。
- 成员数按用户去重。
- 已停用用户不计为有效使用。
- 有效成员存在时阻止停用及不兼容类型变更。
- 继续检查待处理流程任务，避免冻结策略仍在执行时停用角色。

### 4. Agent 节点闭环

- Agent 节点任务必须进入可执行或明确阻断状态，不允许服务身份接单后永久悬挂。
- 自动执行仅允许 Low 风险，并遵守 `AgentProfile` 自主等级、金额和风险上限。
- 永久人工边界不得自动通过。
- Agent 执行需关联 `AgentRun`、`GatewayCall`、任务动作、审计和幂等键。
- 需人工确认时，由具备处理资格的真人确认；服务身份不得自确认。
- 高风险、金额超限、等级不足、Profile 无效或不可解析时明确拒绝。
- 前端展示待执行、待人工确认、已代理完成或已阻断。

### 5. 数字员工选择器

- 流程配置页通过现有 `/api/v1/agents` 获取有效 Agent Profile。
- 使用可搜索选择器展示名称、岗位/说明和稳定 ID。
- 只允许选择有效、可用的数字员工。
- 发布校验失败使用业务语言，不向用户显示裸 GUID。

### 6. 高风险审核驳回

- 新增 `POST /api/v1/iam/access-requests/{id}/actions/reject`。
- 调用现有 `ReviewAccessRequestAsync(..., approve: false)`。
- 通过和驳回都要求审核意见。
- 保留申请人不可自审、已处理状态幂等和审计。
- 页面增加“复核驳回”。

### 7. 人员服务端分页与搜索

- 人员列表使用 `/api/v1/iam/users?page=&pageSize=&search=`。
- 页面提供上一页、下一页、总数和页码。
- 搜索覆盖全量人员，不只当前页。
- 角色成员选择器不得静默只显示前 50 人。
- 保留 `/iam/snapshot` 用于组织树、角色、权限和待审核申请。

### 8. 前端按钮动作权限

- `IamRolesPanel.vue` 和 `IamPeoplePanel.vue` 使用 `auth.can(...)` 控制显示或禁用。
- 普通员工不显示 IAM 管理入口。
- 项目经理只看到授权部门内可执行的角色分配和导航操作。
- 后端 403 仍是最终权限真源。

### 9. 六类处理人策略与转交资格

- 覆盖 `SpecificUser`、`BusinessRole`、`DepartmentManager`、`ProjectOwner`、`InitiatorManager`、`Agent`。
- 覆盖正常解析、缺失处理人阻断、快照冻结、成员变化不影响历史任务。
- 覆盖部门越界、当前处理人/动作权限/部门范围/候选资格联合校验。
- 转交目标必须具备实际处理资格，不能转交给随后必然失败的真人。
