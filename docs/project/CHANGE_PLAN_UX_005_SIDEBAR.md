# UX-005 PMS 风格侧边栏与工作台正文重构变更计划

状态：`complete_deployed_and_frozen`

## 🎯 目标

参考用户 PMS 系统的工作台形态，统一 AIDT 的信息层级和操作路径：

```text
固定应用外壳与侧栏
 → 简洁页面头
 → 关键统计
 → 搜索和分类筛选
 → 全宽业务主体
 → 右上角“介绍”抽屉
```

需要同时解决两类问题：

1. 侧栏裁切、页面滚动后消失、Codex 窄侧栏超长。
2. 正文固定在约 `1260px`、只占页面约三分之二；说明文字占用首屏；列表页缺少
   搜索、分类和明确的扫读顺序。

本需求只重构前端布局、视觉和交互，不改变导航、权限、业务状态或写操作事务。

## 🧭 分阶段范围

### UX-005-A：应用外壳与侧栏

- 应用外壳固定为 `100dvh`。
- 主内容区独立滚动，侧栏不随正文滚动。
- 侧栏品牌区和底部操作固定，中间导航独立滚动。
- 侧栏参考 PMS 的浅色、紧凑、分组折叠和 `38px` 菜单密度。
- 当前部门单开，当前菜单自动进入可视区域。
- `820px` 以下改为带遮罩的左侧抽屉。

### UX-005-B：统一工作台正文框架

建立统一的信息顺序和复用组件：

1. 页面头：标题、当前部门/范围、主要操作、右上角“介绍”。
2. 统计区：3～5 个有业务意义的指标。
3. 筛选区：关键词、部门、状态、来源、日期等。
4. 分类区：全部、待处理、我发起、我参与、需要关注等。
5. 主体区：表格、紧凑列表、左右分栏或看板。
6. 介绍抽屉：用途、使用场景、1～2 个例子、权限与边界。

运营型页面使用完整可用宽度；详情正文和表单可以设置适合阅读的宽度。

### UX-005-C：首批样板页

先迁移以下两个页面，验证框架后再推广：

- “我的工作”
- “AI 听记”

首批不一次性改造所有业务页面。

## 🧠 设计原则

### 先行动，后解释

- 页面首屏优先展示状态、待办、搜索和业务数据。
- 移除标题下方大段 `page-lead` 功能说明。
- 功能说明、背景和例子进入右上角“介绍”抽屉。
- 高风险边界不能只隐藏在介绍中；在具体提交、确认、审批位置继续显示。

### 先缩小范围，再处理内容

- 列表型页面必须先提供搜索和分类。
- “我的事项”不能只依靠分类页签，还要支持搜索和组合筛选。
- “AI 听记”不能把全部记录一次性堆进超长左栏。
- 大数据量筛选优先服务端执行，前端不得只筛选当前页冒充全量结果。

### 统一不等于机械一致

- 统一页面头的顺序、位置和操作习惯。
- 没有统计意义的页面不强行生成四个数字。
- 设计器、画布和长文档保持适合自身任务的布局。

## 📚 PMS 参考

### 侧栏

- 白色面板，侧栏约 `236px`。
- 导航独立 `overflow-y: auto`。
- 菜单项约 `38px` 高、`13px` 字号、`6px` 圆角。
- 分组使用浅色背景和左侧 `3px` 色条。
- 二级菜单缩进并使用细竖线。
- `760px` 以下切换为抽屉。

### 会议与行动正文

- 页面头：标题和说明在左，刷新/导入操作在右。
- 当前部门范围提示。
- 4 个统计卡：待整理、未关闭行动项、来源缺失、敏感会议。
- 筛选栏：关键词、部门、整理状态、来源状态、日期范围、重置。
- 主体：全宽会议表格。

### AIDT 当前差距

- `.main-content` 固定最大宽度 `1260px`；在约 `2304px` 总视口中，
  可用正文约 `2033px`，内容只占其中约 `62%`。
- PMS 当前会议正文使用几乎全部可用宽度。
- “我的工作”已有统计和分类，但没有统一搜索和组合筛选。
- “AI 听记”没有统计和筛选，听记来源一次性铺成很长列表。
- “我的工作”右侧还有快速开始和说明卡，持续挤占事项主体宽度。

## 🧱 统一正文规范

### 页面头

包含：

- 页面标题；
- 当前部门、环境或范围；
- 主要操作；
- 右上角“介绍”文字按钮或带文字的问号按钮。

移除：

- 长 `page-lead`；
- 重复解释系统能力的说明段；
- 不影响当前决策的技术状态长句。

### 统计区

- 桌面 4 列，平板 2 列，移动端 2 列或横向紧凑布局。
- 每张卡只包含指标名、数字和一条短辅助信息。
- 数字必须来自真实 API 或真实聚合；禁止用当前页条数冒充全量指标。

### 筛选区

- 关键词搜索宽度优先。
- 常用筛选保持在第一行。
- 重置按钮固定在行尾。
- 筛选结果数量可见。
- 无结果、加载失败和权限拒绝必须区分。

### 主体区

- 桌面列表优先采用全宽表格或紧凑行。
- 手机使用卡片或纵向表格。
- 固定表头、分页或独立滚动，避免页面无限增长。
- 详情采用右侧面板或独立详情区域，不挤压主列表。

### “介绍”抽屉

从右侧打开，约 `420px`，包含：

1. 这个页面做什么。
2. 什么时候使用。
3. 1～2 个操作例子。
4. 权限、数据和人工边界。

不要使用长篇系统设计说明；每部分控制在短段落或列表。

## 🏠 “我的工作”目标

### 页面头

- 标题：`我的工作`
- 范围：当前部门 / 全部授权范围
- 操作：`发起事项`；其他入口可收进更多操作。
- 右上角：`介绍`

### 统计

- 待我处理
- 今天到期
- 待我确认
- 人工边界

### 筛选

- 搜索标题、项目、业务对象和来源编号；
- 部门；
- 来源类型；
- 状态；
- 优先级；
- 截止时间；
- 重置。

### 分类

- 全部
- 待我处理
- 我发起
- 我参与
- 需要关注

### 主体

建议使用紧凑事项列表：

```text
事项 | 来源 | 当前节点 | 负责人 | 截止时间 | 状态 | 操作
```

- “今日焦点”保留为一条高优先级横条。
- “快速开始”移入“发起事项”下拉菜单。
- “最近来源证据”改为筛选入口或右侧详情。
- “人工边界”说明移入介绍抽屉；实际风险提示仍在提交和确认处显示。
- 移除长期占用宽度的右侧说明栏。

## 🎙️ “AI 听记”目标

### 页面头

- 标题：`AI 听记`
- 范围：当前部门 / 当前环境
- 操作：`导入听记`
- 右上角：`介绍`

### 统计

- 听记总数
- 已分析
- 待确认行动项
- 本周新增

### 筛选

- 搜索标题、参会人、文字稿内容；
- 部门；
- 分析状态；
- 行动项状态；
   - 来源类型；
   - 会议时间范围；
   - 重置。

### 主体

```text
┌──────────────────┬─────────────────────────────────────┐
│ 听记来源          │ 当前听记详情                        │
│ 筛选后的列表      │ 状态、文字稿、行动项表              │
│ 固定高度独立滚动  │ 固定高度独立滚动                    │
└──────────────────┴─────────────────────────────────────┘
```

- 左侧约 `300～340px`。
- 右侧占满剩余宽度。
- 列表使用分页、独立滚动或虚拟列表。
- 选中听记后右侧详情和行动项保持可见。
- 不在标题下长期显示钉钉断连、真实模型未启用等说明；移至介绍抽屉或必要的状态标签。

  若确需新增，先补齐影响分析和测试。
- 不新增数据库表或迁移。
- 不复制 PMS 源码、图标、品牌、蓝色主题或 Ant Design。
- 不在本需求中重做全部业务页面。
- 不将所有详情页强制铺满屏幕。
- 不用前端当前页条数冒充全量统计。
