## 🔍 原有缺陷根因

### 事件状态

`ApplyEventScope` 固定 `AsNoTracking`，分析/确认修改的事件实体未被 EF 跟踪，
所以建议状态已经提交而事件状态仍是旧值。修复方式只对管理读取启用 tracking，
普通列表/GET 仍保持 `AsNoTracking`，避免扩大变更跟踪成本。

### 项目状态

管理动作先在 `AsNoTracking` 上完成权限/范围判定，再读取被跟踪实体执行写入。
权限与数据范围仍复用原查询，不复制授权逻辑；状态、版本、快照、进度、审计仍在一个事务。

### 项目文件证据

原上传只建立 `AttachmentLink`，项目详情依赖 `ProjectRelation`。修复在附件、版本、
AttachmentLink 和审计的同一保存事务中补 `SupportingEvidence` 关系。先走本地跟踪查重，
再查数据库，并由现有唯一索引兜底并发。

### 截止时间

原实现用 `now.Offset`，Worker 的 UTC 上下文把本地 18:00 解释成 UTC 18:00。
新实现由配置解析 IANA 时区，将无时区本地日期明确解释为上海 18:00，再交给 API 的 UTC
序列化与前端本地化。

## 🔐 权限与审计影响

- 无新增权限码或角色。
- 事件确认、项目状态和文件上传继续先做原权限、部门、项目、环境和保密等级校验。
- 不因修复持久化而放宽项目经理、普通成员或平台管理员边界。

## ⚠️ 风险与控制

| 风险 | 控制 |
|---|---|
| 跟踪查询改变普通读取性能 | 只有分析/确认/管理动作启用 tracking |
