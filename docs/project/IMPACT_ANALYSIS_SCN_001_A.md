# SCN-001-A 影响分析

## 🎯 变更目标

让普通用户通过岗位场景目录理解并启动已有业务能力，同时保留对象先行、
流程编排、权限、审计、事务和人工边界的原始责任。

## 🧩 涉及功能 ID

- `SCN-001`
- 复用 `WF-001`、`WF-002`、`WF-003`、`EVT-001`、`TASK-002`、
  `PMO-001`、`PMO-002`、`PMO-003`、`DOC-001`、`MIN-001`、`AGT-003`

## 📁 预期修改

- Domain：场景枚举和生命周期/人工边界规则。
- Application：场景 DTO、端口、错误码。
- Infrastructure：EF 实体、配置、SQL 服务、事务内业务服务适配。
- API：场景目录、管理、生命周期、前置检查和启动端点。
- Database：迁移 017、up/down SQL、DBA 审核。
- Contracts：OpenAPI、前端 TypeScript 类型。
- Tests：Domain、EF、SQL/API、全量回归。

## 🧱 上游与下游

- 上游：当前身份、组织/部门范围、岗位场景目录和启动请求。
- 下游：Metadata 对象类型、BusinessObject 主对象、Workflow 定义/实例/任务、
  PMO 事件与项目任务、Document 文件和附件关联、Minutes 听记来源、
  Agent 身份与运行、Audit 和 Integration Outbox。

## 🔌 API 变化

新增 `/api/v1/scenarios` 当前目录与详情、`/api/v1/scenarios/manage`
管理列表、生命周期动作、版本查询、前置检查和启动端点。全部为增量，
不改变现有对象、流程和项目接口。

## 🗄️ 数据库变化

- 仅新增迁移 017，不修改 001–016。
- 新增 `Scenario` Schema 和 3 张表。
- 所有 JSON 列有 `ISJSON` 检查。
- 场景编码组织内唯一，版本号场景内唯一，启动幂等键唯一。
- 部门、状态、编码、版本和启动时间建立索引。

## 🔐 权限变化

- 新增 `scenario:read/create/update/manage/approve`。
- 普通业务角色只获得 `scenario-read`；平台管理员获得完整治理权限。
- 写请求先校验动作权限、真人身份和部门管理边界。
- 启动再次执行对象、流程、任务、文件、听记、Agent 和永久人工边界校验。

## 🧾 审计与事件

- 场景创建、保存、校验、发布、停用、恢复、回滚和启动写追加式审计。
- 发布和启动写 Outbox；启动结果保存到场景映射，不复制业务状态。

## 🧪 测试范围

- 六类场景定义完整性、发布和启动。
- 普通用户只看到可用场景；草稿、停用、失效、跨部门场景拒绝。
- 部门负责人跨部门拒绝；服务身份治理与启动拒绝。
- 必填附件、对象、流程、Agent 缺失时业务语言拒绝。
- 同键同内容重放、同键异内容冲突、并发修订冲突。
- 启动中途失败回滚，无 `BusinessObject`、流程、任务或映射半成品。
- 历史版本冻结，回滚生成新版本，旧启动仍引用原版本。
- 业务对象反查流程、任务、项目、附件、审计和 AgentRun。

## ⚠️ 回归风险

- 事务内复用现有业务服务时不能提交内层事务。
- 场景引用快照必须冻结稳定编码与版本，不能只保存可漂移名称。
- 启动失败必须连同业务对象、流程、任务、附件关系、审计和幂等记录一起回滚。
- 新权限不得扩大普通员工现有业务权限。
- 六场景模板不能伪装成空壳，每个场景必须引用真实对象或任务服务。

## ↩️ 回滚方式

- 应用回滚到 `req-ui-step6-final1`。
- 数据库恢复部署前全量备份。
- 隔离库验证 017 down 和 re-up；主库最终以备份独立恢复验证。
