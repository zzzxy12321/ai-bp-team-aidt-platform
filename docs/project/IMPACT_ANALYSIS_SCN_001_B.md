# SCN-001-B 影响分析

## 🎯 变更目标

把 7A 已存在的场景后端能力转化为普通员工可按业务目标操作的前端闭环，并确保所有
状态继续来自对象、流程、任务、项目、文件、听记和审计真源。

## 🧩 受影响功能

- 主功能：`SCN-001-B`
- 复用：`UX-003`、`WS-002`、`META-001`、`WF-001`、`WF-002`、`WF-003`、
  `DOC-001`、`MIN-001`、`PMO-001`、`PMO-002`、`PMO-003`、`AGT-003`、`CFG-001`

| 范围 | 预期变化 | 验证 |

## 🧱 数据流

1. `/scenarios` 调用 7A 可见场景 API。
2. 向导上传文件调用现有文件服务，导入/选择听记调用现有听记服务。
3. 预检和启动调用 7A 预检/启动 API。
4. 7A 在同一事务中调用现有对象、流程、事件或项目任务服务。
5. “我的场景”调用新增只读聚合 API。
6. 聚合 API 以 ScenarioLaunch 为索引，实时读取原流程实例、当前任务、项目任务、
   事件状态、对象和证据链接，不向场景表复制状态。
7. 详情页按返回的业务链接跳转现有模块。

## 🔐 权限影响

- 不新增前端权限绕行或第二套角色。
- 聚合 API 只返回当前用户发起或当前身份可访问部门内的启动记录。
- 普通用户目录继续保持仅返回已发布、部门和数据范围适用场景。
- 管理配置继续要求 `scenario:read` 与对应 create/update/manage/approve 权限。
- 场景启动后的节点操作继续使用原任务处理人和原权限。

## ⚠️ 主要风险

| 风险 | 控制 |
|---|---|
| 前端手工计算进度导致漂移 | 启动列表摘要由服务端计算；前端只展示 |
| 场景启动后复制任务 | 只保存既有任务/实例 ID，深链原待办 |
| Demo 样例被误认为生产事项 | 卡片和详情明确显示“受控 Demo 试点样例” |
| 配置输入任意代码 | 仅允许已发布对象类型、有效流程版本、已发布 Agent 和受控材料来源 |
| 高风险动作被 AI 绕过 | 服务端永久边界继续强制；前端明确列出“不做动作” |
| 移动端向导过长 | 七步分步；单步内部再分组 |
| 深链刷新丢失 | 场景和启动详情全部从 URL 与 API 恢复 |
| 旧 E2E 受导航变化影响 | 统一入口，保留既有路径和测试标识 |

## 🧪 回归重点

- 原有 45/45 正式 E2E。
- `/my-work` 六类来源聚合与任务去重。
- 对象创建/更新、流程启动/审批、项目任务、文件上传、听记确认、AgentRun。
- 场景目录、管理生命周期、高风险双人审核。
- OpenAPI 路径数量增加后前后端契约一致。

## ↩️ 回滚与恢复

- 代码回滚到 7A 冻结基线。
- 本批若无结构迁移，直接回滚应用；若有迁移，恢复部署前备份。
- 场景启动数据和既有业务链属于业务真源，回滚应用不删除。
- 历史标签和发布包保持不可变。
