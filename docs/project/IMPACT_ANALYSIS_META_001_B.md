# META-001-B 业务对象建模与动态表单影响分析

## 🎯 结论

本批是 Metadata、BusinessObject、Workflow、Configuration、Workspace、Document、Project、Audit 与 Identity 的跨模块前端编排。主要风险是草稿泄漏、动态字段类型不一致、前端绕过权限、用户候选跨部门泄漏，以及关联证据只显示前端缓存。

## 🖥️ 前端影响

| 范围 | 变更 | 控制 |
|---|---|---|
| 建模工作室 | 类型列表、字段设计器、预览、校验、影响、生命周期、版本 | 只调用 5A API；无任意代码 |
| 动态对象页 | 九类字段、详情、编辑、版本、项目/流程/文件/审计 | 每次保存后重新读取服务端 |
| 流程配置 | 对象类型从文本框改为已发布类型选择 | 草稿/停用类型不出现 |
| 岗位卡片 | 业务对象卡片可选择发布类型编码 | 仍执行原卡片权限/部门/环境 |

## 🧠 后端影响

- 新增业务对象版本、上下文和用户字段候选三个只读端点。
- 普通用户对象类型列表收敛到发布快照，避免草稿字段和未发布类型泄漏。
- 上下文聚合复用原数据权限；不在前端拼装跨模块权限。

## 🗃️ 数据影响

- 新增 014，仅授权既有业务角色使用 `business-object:update`；无表结构变化。
- 业务对象版本读取现有快照 JSON；历史值不改写。
- 项目关联继续写 PMO.ProjectRelation；文件继续写 Document.AttachmentLink。

## 🔐 权限与脱敏

- 建模写动作继续要求 `object-model:*` + platform-admin。
- 对象编辑要求 `business-object:update`、部门/组织和环境范围。
- Core 字段在列表、详情和历史版本中均保持服务端脱敏。
- 用户候选限定当前组织及操作者可见部门。

## ⚠️ 主要风险

1. 管理员 GET 与普通用户 GET 共用列表：必须按角色返回不同字段快照。
2. 发布新类型后旧页面缓存类型：写入后主动重读类型列表。
3. 前端本地校验通过但服务端拒绝：展示 400/409 服务端消息，不以本地状态宣称成功。
4. 历史版本字段已从当前模型删除：按历史和发布定义继续遮蔽 Core。
5. 关联项目/文件调用越权：全部使用现有 API，后端为最终真源。

## 🧪 测试影响

- 前端规则：字段校验、值格式化、状态映射、发布可见性。
- SQL/API：草稿隔离、版本、上下文、候选、并发编辑。
- Vitest：字段设计器和动态表单。
- Playwright：1440/1280/390 管理建模、普通用户录入编辑、权限拒绝和联动回归。
