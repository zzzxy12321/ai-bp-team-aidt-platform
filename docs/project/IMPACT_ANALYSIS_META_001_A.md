# META-001-A 业务对象建模与字段编辑后端影响分析

## 🎯 结论

本批是 Metadata、BusinessObject、Identity、Audit、Workflow 兼容层的纵向切片。主要风险是已发布模型被覆盖、动态字段校验绕过、并发更新丢失和脱敏规则因新字段模型失效。

## 🗃️ 数据影响

| 范围 | 变更 | 控制 |
|---|---|---|
| ObjectType | 增加状态、修订、并发、发布/停用时间和版本号 | 默认回填现有类型为 Published v1 |
| FieldDefinition | 增加默认值、选项、列表/筛选/排序属性 | 现有字段回填安全默认值 |
| ObjectTypeVersion | 新增不可变版本快照 | 版本唯一，历史不更新 |
| BusinessObjectVersion | 已有表继续保存对象快照 | 更新事务内插入，不覆盖旧行 |
| 历史迁移 | 001–012 不变 | 只新增 013 |

## 🧠 后端影响

- 新增对象模型应用端口和 SQL 服务，控制器不再返回 501。
- 对象模型写动作要求对象模型权限、幂等键、期望修订和审计。
- 业务对象更新复用现有仓储，增加字段定义校验、行版本并发、审计和幂等。
- 新建业务对象只允许 Published 类型；既有对象读取不变。

## 🖥️ 前端影响

- 本批无前端改动；现有对象页继续读取扩展后的兼容 DTO。
- 5B 将在新 API 上实现管理界面。

## 🔐 权限影响

| 权限 | 普通员工 | 平台管理员 |
|---|---|---|
| `object-model:read` | 否 | 是 |
| `object-model:create/update/manage/approve` | 否 | 是 |
| `business-object:update` | 否 | 是及现有授权角色 |

系统继续执行服务端 403、组织/部门范围与 Core 脱敏。

## 🔄 兼容影响

- 既有 `string/text/decimal` 数据类型按 Text/LongText/Number 处理，并规范返回。
- 工作流继续以 `objectTypeCode` 关联。
- 删除字段不物理删除字段历史、不清理业务对象 JSON；对象更新保留未提交的旧键。
- PROJECT 类型主对象和 PMO 档案分离关系不变。

## ⚠️ 主要风险

1. 已发布版本被原地覆盖：版本快照只插入不更新。
2. 删除字段破坏旧对象：字段定义删除不级联业务对象，更新时保留旧键。
3. 同一幂等键复用不同内容：请求摘要不一致返回 409。
4. 并发更新丢失：`expectedVersion` + SQL `rowversion`。
5. 非管理员读取 Core：查询层继续按当前字段敏感性遮蔽。

## 🧪 测试

- 域模型：字段类型、属性、兼容、重复 Key 和不兼容变更。
- 应用：权限、幂等、字段校验、并发和审计。
- SQL/API：全生命周期、跨部门、Core 脱敏、五类对象和 PROJECT 回归。
- 迁移：013 up/down/re-up、备份校验和恢复库。
- 发布：全量后端/MCP、正式 E2E、应用回滚和恢复。
