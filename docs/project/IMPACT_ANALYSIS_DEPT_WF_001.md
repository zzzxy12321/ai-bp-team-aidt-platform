# DEPT-WF-001 影响分析

## 🎯 变更目标

在保持单一业务对象和 Elsa 流程真源的前提下，提供部门优先导航、部门自服务普通流程、
节点级动态表单、版本冻结和四部门试点闭环。

## 🧩 涉及功能

- `DEPT-WF-001` 部门优先工作空间与可视化流程设计器
- `NAV-001` 导航
- `IAM-001` 权限与会话
- `CFG-001` 配置中心
- `WF-001` 至 `WF-004` 流程
- `TASK-001`、`WORKFLOW-001` 节点策略与任务动作
- `OBJ-001/META-001` 业务对象与字段
- `DOC-001` 文件与附件
- `MIN-001` 听记
- `AGT-003/AIG-002` 数字员工与规则模拟
- `AUD-001` 审计证据

## 🔗 预期调用链

```text
Navigation API → 已注册路由/权限/部门 → AppLayout
Configuration Page → Configuration API → SqlWorkflowConfigurationService
 → ConfigurationVersion + WorkflowDefinition/WorkflowVersion/NodePolicy
Workflow Page → Task API → 冻结流程与表单版本
 → Application Use Case → WorkflowTask + 表单值 + Audit + Outbox
```

## 🌐 API 与前端影响

- 导航当前树增加来源分组、部门摘要、错误状态和个人偏好完整数据。
- 配置 API 扩展节点及模板生命周期 DTO，但继续使用 `/configurations`。
- 任务运行 API 增加冻结表单定义、表单草稿与随动作提交。
- 前端契约与 OpenAPI 同步；旧字段保持兼容。
- `/configurations` 重做为三段式设计器；`/workflows` 使用业务表单运行。

## 🗄️ 数据库影响

- 优先扩展现有 `ConfigurationVersion`、`WorkflowDefinition`、`WorkflowVersion`、
  `WorkflowNodePolicy`、`WorkflowTask`。
- 导航和配置测试隔离字段可复用现有环境/测试标记；若缺失则只在 018 增量补齐。
- 任务填写值仅保存真实人工输入和冻结定义指针，不复制对象正式字段。
- 配置检查约束 `ISJSON`、SchemaVersion，并为 TaskId、WorkflowVersionId、
  NodeCode、EnvironmentCode 建必要索引。
- 001—017 不修改。

## 🔐 权限和审计影响

- 普通员工只使用本部门已发布模板。
- 部门流程负责人只能创建、编辑、校验和试运行本部门普通模板。
- 普通、低风险、单部门模板可按新 ADR 部门级发布；跨部门和高风险情形继续平台审核。
- 服务身份不能创建、发布、审批或启动流程。
- 越权、保存、提交、发布、停用、恢复、回滚、任务动作和 Agent 确认均写追加式审计。

## 🧪 测试范围

- 导航三层结构、公共入口去重、部门隔离、偏好、旧会话权限刷新、测试隔离。
- 模板多版本/默认模板/生命周期/并发/幂等/回滚。
- 全部字段类型、必填、角色可见/可写、候选范围、敏感等级、附件和冻结版本。
- 任务动作事务回滚、重复提交、并发冲突和永久人工边界。
- 数字员工关联、规则模拟标识和人工确认。
- 四部门试点、1440/1280/390px、原全量 E2E 回归。

## ⚠️ 回归风险

- 现有 `/configurations` 调用方和旧配置 JSON 必须兼容。
- 导航数据迁移不得让旧会话误显示为空或暴露无权限部门。
- 节点字段不得复制业务对象正式值；表单值必须与任务版本绑定。
- 高风险流程不能因部门模板放宽人工边界。
- 迁移失败可能影响所有流程；部署前必须备份、验证和可回滚。

## ↩️ 回滚方式

- 应用回滚到 `req-ui-step7-final1`。
- 018 提供可审阅 down 脚本；仅在确认无新增不可逆业务数据时回滚结构。
- 数据清场只做可恢复退役/标记，不物理删除审计、历史任务或证据。

## ✅ 实现后复核

- 导航与配置均使用测试标记/退役，没有物理删除测试历史。
- 018 只扩展既有导航、配置、流程定义、节点策略和任务，应用表保持 71。
- 任务表单使用现有 `WorkflowTask`，没有新建任务表单值表或业务字段副本。
- 表单写入复用 Application 事务、幂等和版本校验，动作、审计与 Outbox 同事务。
- 部门流程负责人发布权限限制在低风险单部门模板；高风险和跨部门继续平台审核。
- 源码回归通过；正式主库与部署风险仍在发布门禁中关闭。
- 主库 018、final3 正式 E2E、应用回滚、独立恢复和发布包校验均已完成。
