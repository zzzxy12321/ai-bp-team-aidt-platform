# UX-006 全站主栏目页面介绍上下文包

## 🎯 任务

统一 17 个左侧主导航一级栏目的页面头与业务介绍，使用同一个介绍抽屉组件和集中式
静态目录，让用户无需阅读正文长说明即可理解页面用途、典型操作和风险边界。

## 🏷️ 任务类型

前端信息架构、共享组件、静态帮助内容、可访问性和全站回归。默认不修改后端、
数据库、权限语义、流程事务或审计规则。

## ✅ 验收标准

- 每个一级栏目右上角有“介绍”。
- 抽屉包含页面用途、岗位时机、3—5 步路径、至少两个具体例子、数据来源、
  权限范围、人工边界、下一步和相关入口。
- 只描述实际已实现能力。
- 不向员工展示 UUID、节点代码、TraceId、数据库字段等技术语言。
- 无权限页面不显示介绍。
- 抽屉支持关闭按钮、遮罩、Escape 和焦点返回。
- 抽屉内部独立滚动，无内部横向滚动。
- 桌面、1280、820、600×518、390 和 320 宽度无错位或页面横向溢出。
- UX-005 侧栏、我的工作、AI 听记无回归。

## 🌐 API

本功能不调用新 API。页面介绍是静态业务帮助，不写审计、不读取额外业务数据、
不改变页面状态。页面自身继续使用既有 API 和权限。

## 🗄️ 数据

无数据库表结构变更，无数据迁移。静态目录只包含页面标题、业务描述和可选路由链接。

## 🔐 权限与安全

- 介绍入口只在对应页面实际渲染时出现。
- 路由守卫继续阻止无权限用户进入页面。
- 介绍不包含具体用户、具体业务实例或敏感字段值。
- 数字员工、付款、质量放行、配方、设备、合同和重大赔付继续强调永久人工边界。
- 钉钉、外部模型、U9、ERP、DCS 等未连接状态必须如实说明。

## 🚫 明确禁止

- 在每个页面复制抽屉或弹窗逻辑。
- 把介绍内容写入后端、数据库或审计。
- 用尚未实现的真实钉钉、外部模型或外部系统能力编造示例。
- 在介绍中暴露具体 UUID、节点代码、TraceId 或数据库字段。
- 将现场高风险提示全部移入抽屉。
- 为详情页、登录页、无权限页和 404 页面重复增加介绍。
- 修改历史冻结标签、历史发布包或迁移 `001—018`。
