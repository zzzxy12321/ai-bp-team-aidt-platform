## 🎯 目标

把项目详情从“查看、创建、添加成员和管理里程碑”补齐为可编辑、可派发、可关联、可流转且刷新后一致的项目空间：

```text
编辑项目
 → 更换负责人
 → 管理成员
 → 创建项目任务
 → 分配责任与期限
 → 关联文件、听记、流程和证据
 → 更新项目进度
 → 状态流转
 → 刷新后保持一致
```

## 🧱 实现范围

1. 项目详情增加“编辑项目”，可修改名称、目标、阶段、计划日期、保密等级和负责人。
2. 负责人变更继续复用 `PUT /api/v1/projects/{id}`，同一事务内更新主对象版本、负责人和 Lead 成员。
3. 成员区支持新增成员、修改项目角色和移除成员；负责人移除前必须先在编辑项目中完成更换。
4. 新增 `POST /api/v1/projects/{id}/tasks`，直接创建项目任务并校验任务负责人为有效项目成员。
5. 任务创建写入标题、内容、负责人、截止时间、优先级、项目和部门，并记录追加式审计。
6. 项目关联区支持文件、听记、流程实例、业务对象、事件和审计证据；关系摘要随关系保存。
7. 项目进度继续由已完成里程碑与项目任务按同一公式自动重算，不增加可随意覆盖的人工百分比。
8. 状态选择器只允许项目领域规则认可的流转，完成项目仍要求没有未完成任务。
9. 所有写操作后重新读取项目详情，刷新页面保持负责人、成员、任务、关联、进度和状态。

## 🧭 架构决策

- 项目公共状态和版本继续保存在 `BusinessObject`，项目专属字段保存在 `PMO.ProjectProfile`。
- 项目任务继续使用 `PMO.ProjectTask`，不创建第二套任务表；事件确认任务与直接创建任务共用同一状态和进度规则。
- 关系继续使用 `PMO.ProjectRelation`，实体类型白名单和授权目标校验由后端执行。
- 项目文件上传后已有的自动 `SupportingEvidence` 关系保持不变，手工关联仍保证幂等。
- 页面写请求统一经过 `workspaceApi`，不新增前端临时持久化或本地状态数据库。

## 🚫 不在范围

- 不新增迁移、表、字段或第二套任务/证据模型。
- 不开放任意项目百分比覆盖、任意状态跳转或绕过未完成任务检查。
- 不增加文件删除、成员批量导入、任务编辑/取消等新动作。
- 不允许数字员工自动更换负责人、派发任务或改变项目状态。
- 不改变付款、质量放行、配方、设备控制、合同等永久人工边界。
- 不修改历史冻结标签、发布包、迁移 001–011 或数据库备份。

## 🧪 验收

- 编辑项目名称、目标、日期、阶段、保密等级和负责人后刷新保持。
- 新负责人成为唯一 Lead，原负责人转为 Manager，项目主负责人显示同步更新。
- 可添加成员、修改角色和移除非负责人成员；普通成员仍不能管理成员或项目。
- 可直接创建项目任务，负责人必须是有效成员，截止日期按上海时区保存。
- 任务完成后项目进度自动重算，全部任务与里程碑完成后可流转至待验收和已完成。
- 可关联文件、听记、流程、业务对象、事件和审计证据，刷新后关系与证据摘要保持。
- 无效项目、跨部门成员、非成员负责人、过期版本和非法状态流转均被拒绝。
- 桌面、1280px 和 390px 关键路径通过，无页面级横向溢出。
- 原 29/29 正式 E2E 不回归，新增 PMO-003 E2E 通过。
