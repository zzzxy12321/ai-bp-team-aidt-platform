# WS-002 可配置岗位工作台模板影响分析

## 🎯 结论

WS-002 是跨 Identity、EmployeeWorkspace、Project、Workflow、Document、Minutes、Agent、Audit 的只读编排层和配置层。核心风险不是数据模型复杂度，而是模板配置绕过原业务权限、发布版本污染线上以及“尚未接入”被伪装成真实卡片。

## 🧱 数据影响

| 范围 | 变更 | 风险控制 |
|---|---|---|
| 新 Schema `Workspace` | 4 张模板相关表 | 只存引用和受限配置，不存业务数据 |
| 现有 001–011 | 不修改 | 新迁移仅 012 |
| 现有 62 张表 | 不复制、不改写业务语义 | 卡片通过只读查询引用 |
| 模板分配 | 用户/角色/部门/组织默认 | 唯一匹配键 + 明确优先级 |
| 草稿/发布 | 每模板一个可编辑草稿，多个不可变发布版本 | 发布生成新版本；历史不改写 |

## 🧠 后端影响

- 新增 `IWorkbenchService`、SQL 实现、`WorkbenchController` 和 DTO。
- 复用 `AidtDbContext`、`IAuditRepository`、`IIdempotencyStore`、`IClock`。
- 模板解析先执行 `workbench-template:read` 与组织范围，再按命中分配过滤。
- 卡片聚合必须按来源执行原动作权限、组织/部门/项目/环境范围。
- 返回卡片状态、业务名称、Top 事项和深链；不返回无权限 UUID 或物理路径。
- 配置写操作按授权部门和角色判定；发布/恢复同事务写审计与幂等。

## 🖥️ 前端影响

- `DepartmentPage.vue` 从固定三块布局改为模板卡片网格。
- 首次请求失败返回通用工作区，并显示模板不可用提示。
- 卡片显示 Ready/Empty/Error/Denied/NotConnected 状态。
- IAM 新增模板配置页签；普通用户不显示配置技术字段。
- 390px 卡片单列；卡片内容长文本可收缩；禁止横向滚动。

## 🔐 权限影响

| 权限 | 普通员工 | 部门负责人 | 平台管理员 |
|---|---|---|---|
| `workbench-template:read` | 是，仅匹配结果 | 是，授权部门 | 是，组织范围 |
| `workbench-template:manage` | 否 | 是，授权部门 | 是 |
| `workbench-template:publish` | 否 | 是，授权部门 | 是 |

系统模板可复制不可删除；部门负责人不能维护系统模板或跨部门分配。

## 🧪 测试影响

| 层 | 必须覆盖 |
|---|---|
| 单元 | 优先级、回退、卡片配置校验、显隐和排序 |
| SQL/API | 6 模板解析、跨部门、无权限、草稿/发布/恢复、版本历史 |
| Vitest | 模板配置页、卡片状态、部门切换、按钮权限 |
| Playwright | 六岗位差异、未发布不生效、发布生效、回退、无权限、三尺寸 |
| 迁移 | 012 up/down/re-up、主库应用、备份 `RESTORE VERIFYONLY` 和恢复库 |

## ⚠️ 主要风险

1. 模板按角色匹配时错误使用全局 `Roles`，忽略部门范围；必须使用角色分配范围。
2. 卡片通过模板权限泄漏跨部门/项目数据；必须逐卡复用来源权限。
3. 同一部门多个同级模板不确定；必须使用稳定排序和唯一系统默认。
4. 发布覆盖草稿或线上版本；必须版本化并保留历史。
5. “尚未接入”被错误显示为空或 0；必须独立状态。
6. 部门切换缓存旧模板；必须先清空旧数据再加载新部门。
